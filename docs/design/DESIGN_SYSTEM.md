# Design System

FounderLab OS should feel like an operational ledger: precise, restrained,
scannable, and honest about authority.

## Principles

- Prefer tool surfaces over marketing sections.
- Keep controls compact, explicit, and functional.
- Use visible state for gates, checks, previews, and approvals.
- Preserve mobile usability for the founder's phone QA loop.

## Current Visual Language

- Warm mineral surfaces with a near-black green shell and one verified-green
  accent.
- Square ledger modules; avoid generic dashboard card grids and decorative
  rounding.
- Monospace labels for system state and commands.
- Space Grotesk carries interface hierarchy and IBM Plex Mono carries state,
  thresholds, IDs, and timestamps.

## Noesis Extension

- A compact vertical proof rail feeds the live warrant band.
- Editors use pale ledger surfaces and visible field boundaries.
- Emerald indicates verified permission; amber indicates a held action; rose
  indicates a denied warrant.
- Motion is limited to interaction feedback; the decision state must remain
  stable and scannable.
- Mobile places the warrant rail before the long-form editor and keeps import,
  export, and reset available in the sticky header.
