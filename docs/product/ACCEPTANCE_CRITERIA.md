# Acceptance Criteria

## Agent Work

- Routing tier declared before work.
- Repo cartography completed before meaningful edits.
- Affected files, risk, test plan, and rollback plan identified.
- Code changes are smallest safe changes consistent with existing patterns.
- Receipt is produced at handoff.

## Product Work

- User-facing behavior has a visible UI, admin, or API surface.
- Non-goals and constraints are documented for large work.
- Mobile layout is checked for UI changes.
- Reference or simulated capabilities are labeled honestly and cannot imply
  production execution.

## Release Work

- Format, lint, and build are run or a reason is documented.
- Security-sensitive changes get elevated review.
- Vercel preview is used before production.
