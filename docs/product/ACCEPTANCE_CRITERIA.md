# Acceptance Criteria

## Agent Work

- Routing tier declared before work.
- Repo cartography completed before meaningful edits.
- Affected files, risk, test plan, and rollback plan identified.
- Code changes are smallest safe changes consistent with existing patterns.
- Receipt is produced at handoff.

## Product Work

- User-facing behavior has a visible UI, admin, or API surface.
- Non-goals and constraints are documented for large work.
- Mobile layout is checked for UI changes.
- Reference or simulated capabilities are labeled honestly and cannot imply
  production execution.
- The command center has no inert controls or fake operational states.
- The Noesis harness supports editable state, weighted evidence, proportional
  policy, scoped leases, local persistence, validated import/export, audit, and
  downloadable dry-run receipts.
- The probability-flow gate visibly resolves a dependency-closed subset of
  effects from tail risk, first-passage exposure, identity drift,
  reversibility, protected-boundary flux, authority, and observer freshness.
- Transient affect, unresolved contradictions, or trust liabilities cannot
  promote canonical identity; expired observers transitively revoke dependent
  evidence, plans, certificates, leases, and effects.
- The personality interaction 144 system and Identity Bloom 12 by 12 graph use
  separate namespaces and reduction certificates; current weights remain
  labeled research scaffolding.
- Care flow preserves two distinct principals, consent, agency, safety,
  truthfulness, and each right to exit; attachment is never an optimization
  reward.
- Flow receipts replay deterministically and are embedded in the Noesis dry-run
  receipt; input drift invalidates the warrant.
- Protocol imports fail closed on dangling or duplicated references, shared
  observer/node identifiers, circular evidence chains, or relationship effects
  that omit either principal; action cycles remain explicitly visible in the
  receipt.
- The default operator view uses plain-language blocker reasons and shows risk,
  boundary, reduction, and care thresholds while keeping calibration controls
  in accessible disclosure panels.
- Desktop and 390px mobile layouts expose the same core actions without
  horizontal overflow.

## Release Work

- Unit tests, format, lint, and build are run or a reason is documented.
- Security-sensitive changes get elevated review.
- Vercel preview is used before production.
